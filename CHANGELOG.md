### Current state

## [0.1.0] — M1 core runner _(code-complete, not yet built or released)_

### Added

**Project scaffold**

- Repository root is the Unity project root. `Packages/manifest.json` pins URP 14.0.11, Input System 1.7.0,
  Addressables 1.21.21, TextMeshPro 3.0.6, Test Framework 1.1.33 (NUnit 3.13), Newtonsoft-Json 3.2.1.
- `ProjectSettings/ProjectSettings.asset`: IL2CPP, ARM64 only, min API 26 / target current, portrait,
  AAB + Play Asset Delivery, ASTC, Vulkan → GLES3 fallback, incremental GC, linear colour, and the
  `DEV` / `QA` / `PROD` plus feature defines from §2.3.
- 15 assembly definitions — Core, Data, Services.Abstractions, Services, Audio, Controls, Track, Economy, Meta,
  Gameplay, UI, Bootstrap, Editor, Tests.EditMode, Tests.PlayMode — with the §3.3 DAG edges declared up front.
  `Economy`, `Meta`, `UI` and `Services` are an asmdef and no code: the module boundary exists before the
  milestone that fills it, so a wrong dependency shows up in CI rather than in a refactor.

**Core primitives (`Skyrift.Core`)**

- `EventBus` — struct payloads, one static channel per payload type, depth-guarded add/remove during dispatch.
- `ServiceContainer` (composition-time resolution, `TryResolve`), `GameStateMachine<TState>` with a declared
  transition table, `ObjectPool<T>` + `PoolRegistry`, `IClock` with `UnityClock` and a deterministic
  `ManualClock`, `XorshiftRandom` with `Fork(streamName)`, `StableId`, `Result`/`ErrorCodes`, channelled `ILog`.

**Data (`Skyrift.Data`)** — 13 `ScriptableObject` definition/config types (world, chunk, obstacle, collectible
kind, balance, input, scoring, continue, audio, track generation, pool catalog, behaviour catalog, catalog
manifest), `GameDatabase` with per-type repositories, and `ICatalogSource` / `LocalCatalogSource` as the
Addressables swap point for M3 (ADR-0012).

**Controls (`Skyrift.Controls`)** — generated `InputActionAsset`, `TouchInputSource` (swipe/tap gesture
detection), `KeyboardInputSource` for editor and device-less testing, and `InputCommandBuffer`: a ring with an
inclusive time-window expiry so a buffered swipe can never be replayed after it has aged out.

**Track (`Skyrift.Track`)** — `ChunkDefinition` / `ChunkRoot` / `SpawnAnchor`, `TrackGenerator` (weighted,
difficulty-aware, allocation-free per-frame path, safe-fallback branch, `IChunkEligibilityRule` and
`IChunkSelectionWeight` extension points), `TrackStreamer` (coverage → recycle → origin shift in that order),
`WorldOriginShifter` (floating origin, 2048 m default threshold).

**Gameplay (`Skyrift.Gameplay`)** — `PlayerMotor` (lane interpolation, closed-form jump/roll, speed profile,
support surfaces), `PlayerContactSensor`, `CollisionResolver` (two-hit stumble, shield substitution),
`StandardObstacleBehaviours` covering jumpable / rollable / full-blocker / moving / ramp / rooftop,
`ObstacleChunkPopulator`, `ChaserSystem`, `ScoreCalculator` + `ScoreBreakdown`, `RunController` (start, tick
order, pause, crash, continue offer, end, snapshot), and `ContinueOfferPolicies`.

**Audio (`Skyrift.Audio`)** — `AudioService` with an audio-voice pool, a generated mixer with groups, the
adaptive `MusicIntensityDriver`, `RunSfxRouter`, and a synthesised placeholder WAV set.

**Bootstrap** — `GameRoot`, `GameBootstrap`, 5 boot steps with `BootstrapOrder` reserving the 5 slots M3/M5
fill, the `GameFlow` transition table, and a dev-only IMGUI `DebugHud` (fps + frame time + worst frame, flow,
distance, speed, lane, heights, invulnerability, stumbles, chaser proximity, score/combo, live/generated/recycled/fallback
chunks, pools + overflow, input state, music intensity, heap + gen0 count).

**Editor (`Skyrift.Editor`)** — `Tools > Skyrift > Build M1 Greybox` (and Step 1…8 individually) generates URP
renderer assets + three quality tiers, layers, the input actions, placeholder audio + mixer, materials and
prefabs (8 chunks, 6 obstacles, player rig, chaser rig), every data catalog, and wires `Boot.unity`. Idempotent;
even the overwrite variant leaves authored *numbers* alone, so a tuned config survives a rebuild. `CatalogValidator`
checks trigger size against authored footprint, the graze band, lane coverage and spacing, the ramp→roof launch
corridor, and address/pool-key consistency. `SettingsEnforcer` keeps player settings and defines from drifting.

**Tests** — 5 EditMode fixtures (132 cases, 12 of them parameterised) and 3 PlayMode fixtures (26 cases plus 9
coroutines): event-bus and container semantics, state-machine table, pool lifecycle and the per-frame allocation
probe (`ProfilerRecorder`), clock and RNG fork determinism, `StableId` validation, catalog validation rules, the
collision matrix, motor and chaser contracts, scoring breakdown, the input buffer window, chunk eligibility and
selection weights, a corpus walk proving a chunk set cannot dead-end, floating-origin arithmetic, and the greybox
run loop against the shipped scene wiring.

### Changed

- `TECH_DOC.md` → **revision 1.0.2**: §4.4 motor surface, §4.5 `TrackRunContext`, §4.6 pool keys + origin
  re-basing + distance-as-scalar, §4.7 `ContactContext`, §6.2/§6.3 sequences, §2.3 stripping rule, §15 assembly
  column. Contracts were reconciled to what shipped; §4.6's "distance computed from `OriginOffset + local`" was
  corrected because it was wrong, not merely stale.
- New ADR-0013 (contract-unit files), ADR-0014 (pool keys, discrete origin roots, distance scalar), ADR-0015
  (support-surface seam); ADR-0006 and ADR-0007 annotated `Refined by`.
- `README.md` setup now names the greybox build step, which is the actual first thing a new contributor does.

### Fixed

Defects found by reading the code forward during the editor pass — every one of them would have been a
runtime bug on first play:

- The player rig accumulated world Z without bound: it never re-based on an origin shift, so precision degraded
  over a long run and the shift was cosmetic for the only object that mattered.
- The chaser never advanced in Z at all — it held a static offset from the player, so the pressure model was
  animation, not simulation.
- Rooftop landing depended on which rendered frame sampled the surface: a 30 FPS device fell through a roof a
  120 FPS device landed on. Now resolved from the simulated step (scope approved at the time).
- The ramp → roof jump was geometrically unreachable as authored (launch corridor did not clear roof height).
- Correcting the lane-centre vs obstacle-centre error that made the previous fix insufficient — the two together
  are why the corridor now works.

### Known gaps — M1 exit criteria not yet met

- **Nothing is compiled or run.** No `.meta` files, no authored assets, no test run. The 0 B/frame and 60 FPS
  figures are targets with a measuring instrument attached, not measurements.
- Generator-level determinism (`TrackGenerator` producing the same chunk sequence from one seed) is proven only
  at the RNG layer and the rule layer. A full generator fixture needs pooled chunk prefabs, which exist only
  after the greybox build → scheduled with the M1 soak.
- **No 60 s soak PlayMode test yet**; the allocation probe is per-frame inside `PoolingLifetimeTests` only.
- Continues are M2 work. The shipped policy is `NoContinueOfferPolicy` (always refuses); the greybox scene opts
  into `DebugContinueOfferPolicy`, so the crash → continue → decline → results PlayMode coverage is against the
  debug policy and proves the wiring, not the production pricing.
- Addressables is deferred to M3 behind `ICatalogSource`. `prefabAddress` values are asset paths, which is
  Addressables' default addressing, so M3 registers groups without editing definitions.
- Boot steps `SaveService`, `RemoteConfig`, `Consent`, `ServiceAdapters`, `Meta`, `Preload` are **absent, not
  stubbed** (M3/M5). Nothing pretends to be them.
- All art and audio are generated placeholders and labelled replaceable. M1 SFX are 2D. The camera is a greybox
  rig (`RunCameraRig`); player visuals are `GreyboxPlayerVisual`, not an animation rig — there is no
  `PlayerAnimationDriver` yet (§4.4 names it as the intended M6 owner).
- Managed stripping is **Low** on purpose (the codebase is reflection-free). No `link.xml` exists because there
  is nothing to preserve; raising the level is an M5 task landing with the SDKs.
- `CrashCause.FellOutOfWorld` is declared but unproduced — no authored chunk can open a gap under the player
  (ADR-0015 review trigger).
- `GreyboxRunLoopTests` plays real frames, so an unlucky natural crash can shorten a distance assertion. Where
  determinism matters the fixture drives `IRunController.Tick(step)` directly; the residual exposure is stated in
  the fixture rather than hidden behind retries.

### How to verify M1

1. Unity **2022.3.62f1**, open the repository root, let packages restore.
2. `Tools > Skyrift > Build M1 Greybox`, then `Tools > Skyrift > Validate Catalog` — both must report clean.
3. Test Runner: **EditMode** (5 fixtures) then **PlayMode** (3 fixtures). `GreyboxRunLoopTests` self-ignores if
   the greybox has not been built, so an `Ignore` there means step 2 was skipped, not that a test failed.
4. Play `Assets/_Project/Scenes/Boot.unity`: the run auto-starts, the dev overlay shows live state, and its
   buttons pause/resume, restart with a fresh seed, quit the run, and accept or decline a continue offer.
5. Profile a 60 s run with the Frame Debugger / Profiler and check `GC Allocated In Frame` is flat at 0 B
   outside boot. That is the measurement the milestone gate asks for.
